# H-Net 日本語プレ実験方針

作成日: 2026-07-29

## 目的

約 200M の日本語中心 H-Net を本学習する前に、短い比較実験を反復し、stage 0 / 1 の圧縮率、main network、stage 別 learning rate、データ構成の方針を固める。全組合せは探索せず、一度に一つの軸だけを変える。原則 seed 42 を使い、別 seed は最終候補が僅差または不安定な場合だけ確認する。

## 現時点の判断

- 既存の境界制約実験から、stage 0 の UTF-8 強制約（`utf8-soft`、bias `0.2`、loss weight `0.05`）を固定する。
- `(3,3)` を性能と圧縮の本命、`(3,2)` を品質側の対照、`(3,4)` を高圧縮側の参考候補とする。
- 日本語では stage 0 の target `3` が文字に近い粒度になるという仮説は妥当だが、既存実験では stage 0 がすべて `3` だったため、非対称設定で一度だけ検証する。
- main network と learning rate の比較は、stage 配分の方針を決めた後に行う。

## ラウンド方針

### 1. stage 0 / 1 の圧縮配分

最初に `(2,3)` と `(3,2)` を、同一の小規模 packed dataset、architecture、学習量、seed、learning rate で比較する。どちらも累積 target は 6 なので、stage 0 を文字より細かく誘導する場合と stage 1 を細かくする場合の差を見られる。

次に必要な場合だけ `(4,3)` と `(3,4)` を同条件で比較する。stage 0 で文字を越えて早く圧縮する場合と、stage 1 側で高圧縮する場合の差を確認する。

主指標は JA validation BPB、`L1/L0`、`L2/L1`、`L2/L0`、stage 0 の UTF-8 文字途中境界率、throughput、peak memory とする。固定した日本語文脈対照 prompt で stage 1 chunk も観察する。

`(2,3)` が ratio loss と UTF-8 制約を競合させるだけで、品質・安定性・速度の利点がなければ stage 0 は 3 に固定する。`(4,3)` が細粒度情報を失い、同累積 target の `(3,4)` より劣る場合も同様とする。

### 2. main network

選ばれた圧縮設定で、純 Transformer と論文に近い約 Mamba:Transformer = 3:1 の hybrid を最初に比較する。品質差が小さければ throughput、memory、loss spike の少なさを優先する。DC 近傍に attention を置く別配置は、最初の二候補が僅差または不安定な場合だけ追加する。

### 3. stage 別 learning rate

main network の勝者に固定し、stage 0 / stage 1 / main の multiplier `1.5 / 1.2 / 1.0` と `2.0 / 1.5 / 1.0` を比較する。圧縮率の収束が遅い、または不安定性が残る場合だけ論文式の自動計算値を追加する。

### 4. データと最終圧縮率

JA:EN:CODE = 8:1:1 の縮小版を基準とし、pack 後の source 別 byte 数を manifest に保存する。architecture と LR を決めた後、日本語データの一部を長文・Wikipedia・青空文庫系へ置き換える多様性対照を一つだけ作る。

最後に選ばれた条件で `(3,3)` と `(3,2)` を比較し、`(3,4)` は wall-clock の明確な改善があり BPB と chunking の悪化が許容できる場合だけ残す。

## screening 条件

- 既存の 8 時間級データより小さい固定 packed dataset を使う。
- sequence length は 2,048 bytes、seed は 42。
- ペア内で同じ optimizer step 数と input bytes を使う。
- train / validation の重複を避け、JA / EN / CODE 別 validation を固定する。
- 各 run に commit hash、実設定、GPU、ライブラリ版、実行時間、データ manifest、metrics、chunk report、checkpoint を保存する。
- 初期発散、NaN、継続的な UTF-8 境界率悪化があれば早期終了する。

## 最初の実行サイクル

1. Colab の Prepare を実行し、Drive を `/content/drive/MyDrive/hnet_agent/` にマウントする。
2. `mcp_agent` を pull し、利用可能 GPU、Drive 上の既存 dataset / checkpoint / report を監査する。
3. 既存の小規模 dataset を再利用できるか確認する。比較条件を満たさなければ、JA:EN:CODE = 8:1:1 の小規模 template と manifest 出力を追加する。
4. `(3,2)` の短い基準 run を実行し、metrics と chunk report が揃うことを確認する。
5. 同条件で `(2,3)` を実行して比較レポートを Drive に保存する。
6. 結果から stage 0 を 3 に固定するか、次の `(4,3) vs (3,4)` 比較が必要かを決める。
